# 2026-09-11 Bluesky 贴图失败排查

## 结论：两个问题叠加
1. **根因：MAIN world 上传 helper 在 WXT 迁移时丢了注册**
   - `src/contents/helper.ts` 原带 `export const config: PlasmoCSConfig = { matches: [bsky.app 等 6 条], world: "MAIN", run_at: "document_start" }`
   - 迁移 commit 91c64f9 删掉该 config，换成"从未注册"的注释；但 WXT 只扫 `src/entrypoints/*.content.ts`，`src/contents/` 不注册
   - 实测 `.output/chrome-mv3/manifest.json` 的 content_scripts 仅 `extension.js` + `scraper.js`
   - 后果：`window.postMessage({type:"BLUESKY_IMAGE_UPLOAD"})` 无接收方 → `handleBlueskyImageUpload` 成死代码
   - 影响面（同一 helper）：bluesky 图/视频、bilibili 图片、v2ex 编辑器、xiaoheihe 图/视频、weibo 视频
2. **元素改版（bsky.app 实测，2026-09-11）**
   - `button[data-testid="openGalleryBtn"]` 已不存在 → 改为 `button[data-testid="openMediaBtn"]`（aria "Add media to post"）
   - 点击后创建 `input[type=file][data-testid="file-input"]`（accept 含 image/*、video/*，multiple）
   - `composeFAB` 也已不存在（dynamic 有 aria-label "Compose new post" 兜底；video/bluesky.ts 没有兜底 → 视频路径直接 return）
   - 仍有效：`div[contenteditable="true"]`、`button[aria-label="Publish post"]`/`[data-testid=composerPublishBtn]`、`openGifBtn`

3. **时序问题（实测新发现）**：bsky 收到文件后要异步处理约 1s 才在撰写框里生成缩略图，
   而原 `DynamicBluesky` 在 postMessage 之后立刻点 Post → 会发出"有文字没图"的帖。

## 已实施修复
- 新增 `src/entrypoints/helper.content.ts`：`world: "MAIN"` + `runAt: "document_start"` + 旧 6 条 matches，
  静态 import `../contents/helper` 保留实现（WXT 只扫 entrypoints，实现留在 contents/ 里）
- `src/contents/helper.ts`：开头的"未注册"注释改成说明注册方式
- `src/contents/helper/bluesky.ts` 重写：
  - `openGalleryBtn` → `openMediaBtn`（图片/视频同一入口），并去掉 `openGifBtn` 那个错误的视频入口
  - **必须趁 input 还挂在 DOM 上派发 change**：bsky 的 file input 是临时节点，文件选择器一关就被摘掉，
    摘掉后再派发 change 不会冒泡到它的容器监听 → 静默失败。所以删掉了原来 `disabled=true` + sleep(1000) 再派发的写法
  - `isProcessingImage/Video` 加 try/finally，避免 waitForElement reject 后永久卡死
- `src/sync/dynamic/bluesky.ts`：新增 `checkImageAttached()`，轮询 `[data-testid="selectedPhotoImage"]`
  等到预期张数贴入再发布；超时则 warn + 跳过自动发布（对齐 chejiahao 的"未确认不上传就跳过"先例）
- `src/contents/helper/bilibili.ts`：`import { createdInputs } from "."` → `"../helper"`（tsc 一直报的错）

## 验证
- 实测（chrome-devtools MCP 在 bsky.app 撰写框里复现整套注入）：点 openMediaBtn → 1ms 内出现 file input →
  同一任务里 `.files=` + 派发 change → ~1s 后 `selectedPhotosView`/`selectedPhotoImage` 出现（3 张图 count=3），
  ALT 编辑器跟着弹出 → 图片确实贴进了撰写框
- 反例：延迟 1s 后再派发 change → 无任何反应（input 已被摘掉）
- `pnpm build` 绿，manifest 里 content_scripts 多了 `helper.js` + `world: "MAIN"`；
  helper.js 内含全部 6 个平台分支
